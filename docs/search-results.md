# Результаты поиска

## 1. Введение

### 1.1. Задача документации

Документ описывает бизнес-логику и пользовательские сценарии вывода результатов поиска в системе NetVision. Основной фокус - представление найденных проездов транспортных средств в журнале и на карте, а также механики анализа событий: карточки сработок, кластеризация, маршруты, типовые точки, фильтрация, сортировка и переход к архивной точке.

Документ предназначен для синхронизации ожиданий между бизнес-заказчиком, аналитиками, дизайном, разработкой, тестированием и эксплуатацией. Он должен использоваться как основа для декомпозиции задач, проектирования интерфейса, подготовки тест-кейсов и приемки результата.

### 1.2. Задача доработки

Доработка должна обеспечить единый режим просмотра результатов поиска, в котором Пользователь может:

- переключаться между журнальным и картографическим представлением;
- анализировать отдельные проезды и группы проездов;
- просматривать подробную карточку сработки с данными и фотоматериалами;
- исследовать маршруты ТС по дням и государственным регистрационным номерам;
- видеть зоны концентрации фиксаций через типовые точки маршрута;
- переходить от найденного проезда к архивной точке на потоке устройства.

Функции отчетности, поиска двойников и машин сопровождения фиксируются в документе как будущий объем работ и не входят в ближайшую реализацию.

## 2. Термины и определения

| Термин | Описание |
| --- | --- |
| Пользователь | Авторизованный пользователь системы, имеющий права на выполнение поиска и просмотр результатов. |
| Результат поиска | Набор проездов/сработок, найденных по заданным параметрам запроса. |
| Проезд | Факт фиксации транспортного средства устройством контроля в определенные дату и время, в определенной географической точке. |
| Сработка | Событие, сформированное системой по результату фиксации проезда и сопоставления с условиями поиска. В рамках документа термины "проезд", "событие" и "сработка" могут использоваться близко, если не требуется техническое различение. |
| Карточка сработки | Детальное представление одного события с атрибутами, фотоматериалами и действиями Пользователя. |
| Журнал проездов | Табличное представление результатов поиска. |
| Карта | Географическое представление результатов поиска в виде маркеров, кластеров, маршрутов и типовых точек. |
| Маркер | Точка на карте, соответствующая одному проезду. |
| Кластер | Агрегированная точка на карте, объединяющая несколько проездов, попавших в одну географическую область или отображаемых близко друг к другу на текущем масштабе. |
| Маршрут | Последовательность точек фиксации одного ТС за один календарный день или иной выбранный период группировки. |
| Типовая точка маршрута | Точка фиксации, используемая для анализа повторяемости маршрута; наиболее часто встречающиеся точки выделяются отдельно. |
| Архивная точка | Фрагмент/позиция архивного потока устройства, соответствующая моменту фиксации проезда. |

## 3. Объем реализации

### 3.1. Входит в текущий объем

- два представления результатов поиска: журнал и карта;
- переключение между журналом и картой без потери контекста поиска;
- отображение маркеров и кластеров на карте;
- раскрытие содержимого кластера;
- просмотр карточки сработки;
- фильтрация и сортировка результатов в журнале;
- отображение маршрутов ТС на карте с группировкой по дням и номерам ТС;
- отображение типовых точек маршрута с выделением 5% наиболее частых точек;
- боковая панель со списком карточек событий;
- группировка бокового списка по маршрутам при включенном режиме маршрутов;
- переход от проезда к архивной точке на потоке устройства.

### 3.2. Не входит в текущий объем

Следующие пользовательские истории должны быть учтены при проектировании интерфейса и модели данных, но реализуются позднее:

- US.IF.10.8 - перечень двойников по заданному ТС;
- US.IF.10.9 - перечень машин сопровождения ТС;
- US.IF.10.13 - скачивание отчета по результатам поиска;
- US.IF.10.14 - скачивание отчета в форматах PDF, Excel, DOCX;
- US.IF.10.15 - отображение корректных вводных данных запроса в отчете;
- US.IF.10.16 - сохранение сформированного отчета в личном кабинете.

## 4. Бизнес-требования

### US.IF.10.1. Просмотр результатов поиска в двух представлениях

Как Пользователь, я хочу иметь возможность просматривать результаты поиска в двух представлениях, чтобы выбирать наиболее удобный способ анализа:

- табличный вид - журнал проездов;
- графический вид - карта с маркерами и кластерами.

### US.IF.10.2. Агрегация проездов в кластер

Как Пользователь, я хочу, чтобы при наличии нескольких проездов в одной географической точке или при уменьшении масштаба карты система агрегировала их в кластер с отображением количества сработок, чтобы не перегружать карту и быстро оценивать плотность событий.

### US.IF.10.3. Просмотр содержимого кластера

Как Пользователь, я хочу видеть содержимое кластера и отдельные точки проездов с возможностью получить детальную информацию по каждой из них.

Содержимое кластера может раскрываться:

- по клику на кластер;
- при увеличении масштаба карты;
- через фильтрацию перечня атрибутов на панели результатов.

### US.IF.10.4. Просмотр карточки сработки

Как Пользователь, я хочу иметь возможность посмотреть карточку сработки со всеми данными и фотоматериалами, чтобы подробно изучить материал.

### US.IF.10.5. Фильтрация и сортировка результатов

Как Пользователь, я хочу иметь возможность фильтровать и сортировать полученные результаты поиска по расширенному перечню атрибутов, чтобы углубленно анализировать список.

Применимо только к журнальному представлению.

### US.IF.10.6. Отображение маршрутов ТС на карте

Как Пользователь, я хочу видеть маршруты ТС на карте, сгруппированные по дням и по номерам ТС, с временными метками и указанием направления движения, чтобы понимать, как ТС двигалось, и анализировать его поведение.

### US.IF.10.7. Отображение типовых точек маршрута

Как Пользователь, я хочу видеть на карте типовые точки маршрута - все точки фиксации за период поиска, при этом 5% наиболее часто встречающихся выделяются особым цветом, чтобы оценить зоны концентрации.

### US.IF.10.8. Перечень двойников

Как Пользователь, я хочу получать перечень двойников по заданному ТС, чтобы эффективнее проводить оперативно-разыскные мероприятия.

Статус: будет реализовано позднее.

### US.IF.10.9. Перечень машин сопровождения

Как Пользователь, я хочу получать перечень машин сопровождения ТС, чтобы расширить варианты поиска.

Статус: будет реализовано позднее.

### US.IF.10.10. Переключение между картой и журналом

Как Пользователь, я хочу иметь возможность переключаться между картой и журналом проездов в режиме просмотра результатов, чтобы использовать разные варианты анализа.

### US.IF.10.11. Боковая панель со списком карточек событий

Как Пользователь, я хочу видеть на боковой панели список карточек событий с краткой информацией о каждом проезде. Список должен иметь возможность сворачиваться и разворачиваться.

### US.IF.10.12. Группировка карточек по маршрутам

Как Пользователь, я хочу, чтобы при включении режима отображения маршрутов список карточек событий группировался по маршрутам по ТС и датам фиксации, чтобы видеть структурированную информацию.

### US.IF.10.13. Скачивание отчета

Как Пользователь, я хочу иметь возможность скачивать отчет по результатам поиска для дальнейшей обработки вне системы.

### US.IF.10.14. Форматы скачивания отчета

Как Пользователь, я хочу иметь возможность скачивать отчет в разных форматах - PDF, Excel, DOCX, чтобы выбирать удобный для конкретной ситуации.

Статус: будет реализовано позднее.

### US.IF.10.15. Вводные данные запроса в отчете

Как Пользователь, я хочу, чтобы в скачанном отчете содержались корректные вводные данные запроса: временной диапазон и параметры поиска, чтобы была ясна основа, на которой построен отчет.

Статус: будет реализовано позднее.

## 5. Общие принципы отображения результатов

1. Результаты поиска должны быть связаны с исходным поисковым запросом. Пользователь должен понимать, по каким параметрам получен текущий набор данных.
2. Переключение между журналом, картой и режимами карты не должно запускать новый поиск, если Пользователь не изменил параметры запроса.
3. Выбранный результат должен синхронизироваться между представлениями:
   - выбор строки в журнале подсвечивает соответствующую точку на карте;
   - выбор маркера на карте подсвечивает соответствующую карточку в боковой панели и строку журнала, если журнал открыт;
   - выбор карточки в боковой панели центрирует карту на событии или маршруте.
4. Если часть данных недоступна, интерфейс должен явно показывать причину: нет координат, нет фото, нет доступа к архиву, событие удалено или архивный поток недоступен.
5. Данные должны отображаться с учетом прав Пользователя. Если Пользователь не имеет доступа к устройству, фотоматериалам или архиву, соответствующее действие недоступно.

## 6. Журнальное представление

### 6.1. Назначение

Журнал проездов предназначен для детального анализа результатов в табличном виде. Это основное представление для фильтрации, сортировки, сравнения атрибутов и перехода к карточке конкретной сработки.

### 6.2. Минимальный набор колонок

Рекомендуемый состав колонок:

- дата и время фиксации;
- государственный регистрационный номер ТС;
- регион номера;
- марка/модель ТС, если определены;
- цвет ТС, если определен;
- тип ТС, если определен;
- направление движения;
- устройство/камера фиксации;
- адрес или описание места фиксации;
- координаты фиксации;
- статус распознавания номера;
- источник события;
- наличие фотоматериалов;
- ссылка/действие для открытия карточки сработки;
- ссылка/действие для перехода к архивной точке.

Фактический набор колонок может быть шире, если система хранит дополнительные атрибуты события.

### 6.3. Фильтрация

Фильтрация применяется только к журнальному представлению и должна позволять сузить уже полученный набор результатов без изменения исходного поискового запроса.

Поддерживаемые группы фильтров:

- время фиксации: период, дата, часовой диапазон;
- ТС: номер, регион, марка, модель, цвет, тип;
- место фиксации: устройство, камера, адрес, район/зона, координатная область;
- событие: наличие фото, качество распознавания, источник события, тип сработки;
- маршрутные признаки: номер маршрута/группы, дата маршрута, последовательность точки;
- доступность данных: есть архивная точка, есть фотоматериалы, есть координаты.

Фильтры должны быть сбрасываемыми. При сбросе Пользователь возвращается к полному набору результатов текущего поиска.

### 6.4. Сортировка

Сортировка должна поддерживаться по ключевым атрибутам:

- дата и время фиксации;
- номер ТС;
- устройство/камера;
- адрес/место фиксации;
- направление движения;
- качество распознавания;
- наличие фотоматериалов;
- маршрутная группа.

По умолчанию результаты сортируются по времени фиксации. Направление сортировки по умолчанию - от более ранних событий к более поздним для маршрутного анализа и от более поздних к более ранним для оперативного просмотра, если такой режим задан настройками продукта.

### 6.5. Действия со строкой журнала

Для каждой строки должны быть доступны действия:

- открыть карточку сработки;
- показать событие на карте;
- перейти к архивной точке, если доступна;
- раскрыть фотоматериалы, если доступны.

## 7. Картографическое представление

### 7.1. Назначение

Карта предназначена для пространственного анализа результатов поиска: оценки плотности событий, просмотра отдельных точек, кластеров, маршрутов и типовых точек.

### 7.2. Режимы карты

Карта должна поддерживать следующие режимы:

1. **События** - отображение отдельных маркеров и кластеров.
2. **Маршруты** - отображение линий движения ТС, временных меток и направления.
3. **Типовые точки** - отображение всех точек фиксации за период поиска с выделением 5% наиболее частых.

Режимы могут быть взаимоисключающими или комбинируемыми, если это не перегружает интерфейс. При конфликте визуальных слоев приоритет должен быть у выбранного Пользователем активного режима.

### 7.3. Маркеры событий

Один маркер соответствует одному проезду. Маркер должен позволять:

- визуально определить местоположение события;
- открыть краткую карточку события по клику или наведению;
- перейти к полной карточке сработки;
- выделить соответствующую карточку в боковой панели;
- показать направление движения, если данные доступны.

Если у события отсутствуют координаты, оно не отображается на карте, но остается доступным в журнале и боковой панели с признаком "нет координат".

### 7.4. Кластеризация

Кластеризация должна применяться в двух случаях:

- несколько проездов имеют одинаковую или практически совпадающую географическую точку;
- на текущем масштабе карты маркеры расположены слишком близко друг к другу и затрудняют анализ.

Кластер должен отображать количество входящих сработок. При необходимости кластер может визуально различаться по размеру или цвету в зависимости от количества событий.

Правила работы с кластером:

1. Клик по кластеру показывает его состав в боковой панели или во всплывающем списке.
2. Если дальнейшее увеличение масштаба позволяет разделить события, карта должна приблизиться к области кластера.
3. Если события находятся в одной точке и не разделяются масштабом, Пользователь должен получить список входящих событий.
4. Выбор события внутри кластера открывает его карточку или подсвечивает соответствующий маркер/позицию.
5. Фильтрация в журнале должна влиять на набор событий, участвующих в кластеризации, если карта отображает отфильтрованный набор.

### 7.5. Боковая панель событий

Боковая панель отображается рядом с картой и содержит список кратких карточек событий.

Краткая карточка события должна содержать:

- дату и время фиксации;
- номер ТС;
- устройство/камеру;
- место фиксации;
- направление движения, если доступно;
- миниатюру фото, если доступна;
- признаки наличия полной карточки и архивной точки.

Панель должна поддерживать состояния:

- развернута;
- свернута;
- пустое состояние при отсутствии результатов;
- состояние "нет событий на текущем участке карты", если применена фильтрация по видимой области.

При выборе карточки карта центрируется на событии, а маркер выделяется.

## 8. Карточка сработки

Карточка сработки является основным детальным представлением события.

### 8.1. Состав данных карточки

Карточка должна включать:

- идентификатор события;
- дату и время фиксации;
- государственный регистрационный номер и регион;
- распознанные и подтвержденные атрибуты ТС;
- устройство, камеру, поток или канал фиксации;
- адрес/место фиксации;
- координаты;
- направление движения;
- фотоматериалы: обзорное фото, фото номера, дополнительные кадры при наличии;
- качество/уверенность распознавания, если используется;
- связь с маршрутом, если событие входит в маршрутную группу;
- доступные действия: показать на карте, перейти к архивной точке, вернуться к списку.

### 8.2. Фотоматериалы

Фотоматериалы должны отображаться так, чтобы Пользователь мог:

- открыть изображение в увеличенном виде;
- переключаться между доступными кадрами;
- понять, если фото отсутствует или недоступно из-за прав доступа;
- сопоставить время фото со временем события.

## 9. Маршруты ТС

### 9.1. Группировка маршрутов

Маршруты строятся по результатам поиска и группируются:

- по государственному регистрационному номеру ТС;
- по дате фиксации;
- при необходимости - по непрерывным временным интервалам, если между фиксациями есть существенные разрывы.

Базовое правило: один номер ТС + один календарный день = одна маршрутная группа, если продуктом не задано иное правило сегментации.

### 9.2. Отображение маршрута на карте

Маршрут должен отображаться как последовательность точек фиксации, соединенных линией по времени события. На карте должны быть видны:

- начальная и конечная точки маршрута;
- промежуточные точки;
- временные метки ключевых точек;
- направление движения;
- различение нескольких маршрутов цветом или стилем линии;
- выделение выбранного маршрута.

Если по части событий нет координат, они не участвуют в линии маршрута, но должны отображаться в боковой панели маршрута с признаком "нет координат".

### 9.3. Группировка бокового списка по маршрутам

При включенном режиме маршрутов боковая панель должна группировать карточки событий по маршрутам.

Группа маршрута должна содержать:

- номер ТС;
- дату маршрута;
- количество точек фиксации;
- временной диапазон маршрута;
- список событий в хронологическом порядке;
- возможность свернуть/развернуть группу.

Выбор группы маршрута должен подсвечивать соответствующую линию на карте. Выбор конкретной точки внутри группы должен выделять точку маршрута и открывать краткую информацию о событии.

## 10. Типовые точки маршрута

Режим типовых точек показывает все точки фиксации за период поиска и помогает выявлять зоны концентрации.

### 10.1. Расчет частоты

Для каждой географической точки или нормализованной зоны рассчитывается количество фиксаций за выбранный период. Если несколько устройств находятся очень близко, продуктовая команда должна определить правило нормализации: точная координата, радиус, зона, устройство или адрес.

### 10.2. Выделение 5% наиболее частых точек

5% точек с максимальным количеством фиксаций должны выделяться особым цветом. Если количество точек не позволяет выделить ровно 5%, применяется округление вверх минимум до одной точки при наличии результатов.

Пример: если найдено 37 уникальных точек, 5% = 1,85; выделяются 2 наиболее частые точки.

### 10.3. Отображение и взаимодействие

Для каждой типовой точки Пользователь должен видеть:

- количество фиксаций;
- список связанных событий;
- распределение по датам/времени при наличии такого представления;
- переход к событиям, входящим в точку.

## 11. Переход к архивной точке

Переход к архивной точке должен быть доступен из:

- строки журнала;
- карточки сработки;
- краткой карточки события на боковой панели;
- всплывающей карточки маркера на карте.

При переходе система должна открыть архивный поток устройства в момент фиксации события или максимально близко к нему с учетом доступности архива.

Если архив недоступен, Пользователь должен увидеть понятное сообщение:

- архив не найден;
- истек срок хранения;
- нет прав на просмотр;
- устройство/поток недоступен;
- временная метка события некорректна.

## 12. Состояния и исключительные ситуации

| Ситуация | Ожидаемое поведение |
| --- | --- |
| Нет результатов поиска | Показать пустое состояние в журнале и на карте, сохранить параметры запроса. |
| Часть событий без координат | Показать события в журнале и боковой панели, не отображать на карте, явно указать отсутствие координат. |
| Часть событий без фото | Показать карточку без фото с причиной отсутствия. |
| Большое количество результатов | Использовать пагинацию/виртуализацию в журнале, кластеризацию на карте, индикатор загрузки слоев. |
| Ошибка загрузки карты | Сохранить доступность журнала, показать сообщение об ошибке картографического слоя. |
| Ошибка загрузки карточки | Показать сообщение и возможность повторить действие. |
| Недостаточно прав | Скрыть или заблокировать недоступные действия с объяснением причины. |
| Применены фильтры без совпадений | Показать пустое состояние отфильтрованного набора и кнопку сброса фильтров. |

## 13. Критерии приемки

### US.IF.10.1

- Пользователь видит результаты поиска в журнале.
- Пользователь видит те же результаты на карте, если у событий есть координаты.
- Представления доступны из единого режима просмотра результатов.

### US.IF.10.2

- Несколько близко расположенных маркеров агрегируются в кластер на малом масштабе.
- Кластер показывает количество входящих сработок.
- При изменении масштаба состав кластеров пересчитывается.

### US.IF.10.3

- Пользователь может раскрыть кластер.
- Пользователь видит список событий внутри кластера.
- Пользователь может открыть карточку сработки для события из кластера.

### US.IF.10.4

- Карточка сработки открывается из журнала, карты и боковой панели.
- Карточка содержит ключевые атрибуты события и фотоматериалы при наличии.
- При отсутствии данных карточка показывает понятное состояние.

### US.IF.10.5

- В журнале доступны фильтры по расширенному набору атрибутов.
- В журнале доступна сортировка по ключевым колонкам.
- Фильтрация и сортировка не применяются как обязательная функция к картографическому представлению.

### US.IF.10.6

- Маршруты отображаются на карте по номеру ТС и дате.
- Точки маршрута соединены в хронологическом порядке.
- На маршруте отображаются временные метки и направление движения.

### US.IF.10.7

- На карте отображаются все точки фиксации за период поиска.
- 5% наиболее частых точек выделены особым цветом.
- Пользователь может посмотреть количество фиксаций и связанные события по точке.

### US.IF.10.10

- Пользователь может переключаться между картой и журналом.
- Переключение не сбрасывает результаты поиска.
- Выбранный результат сохраняет контекст при переходе между представлениями.

### US.IF.10.11

- На карте доступна боковая панель с краткими карточками событий.
- Панель можно свернуть и развернуть.
- Выбор карточки синхронизирован с картой.

### US.IF.10.12

- При включении режима маршрутов боковая панель группирует события по номеру ТС и дате.
- Группы можно раскрывать и сворачивать.
- Выбор группы или события подсвечивает соответствующий маршрут или точку на карте.

### US.IF.10.17

- Из проезда доступен переход к архивной точке, если архив существует и у Пользователя есть права.
- Архив открывается на момент фиксации или ближайшую доступную позицию.
- При невозможности перехода Пользователь видит причину.

## 14. Отложенные требования

Отложенные требования должны быть видимы в бэклоге и учитываться при проектировании текущих компонентов, чтобы не блокировать будущие расширения.

| История | Будущая возможность | Влияние на текущую архитектуру |
| --- | --- | --- |
| US.IF.10.8 | Перечень двойников по заданному ТС | Нужна расширяемая модель карточки ТС и результатов аналитики. |
| US.IF.10.9 | Перечень машин сопровождения | Нужна возможность связывать события разных ТС и показывать аналитические группы. |
| US.IF.10.13 | Скачивание отчета | Желательно отделить данные результата от визуального представления. |
| US.IF.10.14 | Форматы PDF, Excel, DOCX | Требуется форматно-независимая модель отчета. |
| US.IF.10.15 | Вводные данные запроса в отчете | Нужно сохранять параметры запроса вместе с результатом. |
| US.IF.10.16 | Сохранение отчета в личном кабинете | Понадобятся сущности сохраненного отчета и права доступа к нему. |
