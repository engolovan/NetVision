# Черные и белые списки номеров

## 1. Назначение и цель документации

Документ фиксирует возможности, правила работы и требования к черным и белым спискам номеров в личном кабинете: создание списков, настройку периода и камер, загрузку номеров, уведомления, лицензии, права и аудит.

## 2. Цель доработки

Реализовать персональные списки номеров для будущего точечного поиска по выбранным камерам и периоду действия.

## 3. Термины

| Термин | Определение |
| --- | --- |
| Номер | Государственный регистрационный номер транспортного средства, введенный пользователем или распознанный камерой. |
| Список номеров | Набор номеров с едиными настройками типа, периода действия, камер и уведомлений. |
| Черный список | Список номеров, по которым пользователь хочет получать срабатывания как по контролируемым или нежелательным ТС. |
| Белый список | Список номеров, по которым пользователь хочет получать срабатывания как по доверенным, разрешенным или отдельно контролируемым ТС. |
| Срабатывание | Факт совпадения распознанного номера с активным списком с учетом периода действия, камеры, лицензии и прав. |
| Период действия | Интервал даты и времени, в котором список участвует в поиске. |
| Камера | Источник распознавания номеров, на котором применяется список. |

## 4. Уточнения бизнес-логики

1. Черный и белый списки в рамках текущих требований работают как списки прямого совпадения: срабатывание создается, если распознанный номер входит в активный список.
2. Если потребуется логика исключения, например "уведомлять обо всех номерах, кроме белого списка", ее нужно оформить отдельным режимом и отдельными требованиями.
3. Список применяется только к будущим событиям распознавания. Ретроспективный поиск по архиву не входит в текущий объем, если не будет согласован отдельно.
4. Пользователь видит и настраивает только те камеры, списки и срабатывания, на которые у него есть права.
5. Номера должны нормализоваться единообразно для ручного ввода, пакетной загрузки, хранения и поиска.

## 8. Требования к данным

### 8.1. Список

Список должен хранить минимум: идентификатор, владельца, название, тип, статус, период действия, выбранные камеры или группы камер, настройки уведомлений, дату создания, автора создания, дату изменения, автора изменения и блокирующие причины, если список не может применяться.

### 8.2. Номер в списке

Номер в списке должен хранить минимум: идентификатор, идентификатор списка, исходное значение, нормализованное значение, комментарий при наличии, дату добавления, автора добавления и источник добавления.

### 8.3. Срабатывание

Срабатывание должно хранить минимум: идентификатор, идентификатор списка, тип списка на момент срабатывания, номер, идентификатор события распознавания, камеру, дату и время события, дату создания срабатывания, владельца списка и статус уведомления.

| AC.IF.4 | Срабатывание не создается, если список неактивен, пуст, не имеет доступных камер или заблокирован лицензией. |
