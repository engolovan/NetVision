# Результаты поиска ТС. Требования к UI и поведению

## 1. Введение

### 1.1. Задача документации

Документ фиксирует бизнес-требования, функциональные требования, нефункциональные требования и основные пользовательские сценарии для экрана вывода результатов поиска транспортных средств в NetVision.

Документ учитывает текущий UI-макет:

- карту с результатами поиска;
- компактную плашку навигации над картой;
- плашки активных поисков на карте;
- боковую панель с результатами, фильтрами, сортировкой, маршрутами и формой отчета.

### 1.2. Задача доработки

Реализовать вывод результатов поиска в разных форматах с возможностью:

- просмотра событий на карте;
- просмотра краткого списка событий в боковой панели;
- просмотра маршрутов;
- фильтрации результатов;
- выбора одной активной сортировки;
- формирования запроса на отчет по текущему поиску.

### 1.3. Границы текущего согласования

В рамках текущего документа описываются:

- экран просмотра результатов поиска;
- отображение событий и маршрутов;
- фильтры и сортировка в боковой панели;
- точка входа в отчеты и форма настройки отчета;
- просмотр нескольких результатов поиска на карте.

Не описываются подробно:

- создание и запуск поискового запроса;
- внутренний механизм формирования файла отчета;
- черные и белые списки;
- алгоритмы выявления двойников и машин сопровождения.

### 1.4. Общий подход

Пользователь должен видеть результаты поиска в нескольких представлениях, чтобы выбрать удобный способ анализа:

- карта;
- список событий;
- маршруты;
- журнал проездов, если он доступен в продуктовой конфигурации.

Состояние выбранного поиска, активных фильтров, сортировки, режима карты и боковой панели должно сохраняться при переключении между представлениями.

### 1.5. Правило именования требований

Идентификаторы требований должны использовать точки как разделители.

Корректные форматы:

- `US.IF.10.x` - пользовательские истории;
- `FR.IF.10.x.y` - функциональные требования;
- `NFR.IF.10.x.y` - нефункциональные требования;
- `UC.IF.10.x` - пользовательские сценарии.

Дефисные форматы, дублирующиеся номера и пропущенные точки не используются.

### 1.6. Глоссарий

| Термин | Определение |
| --- | --- |
| Пользователь | Авторизованный пользователь NetVision, имеющий права на поиск и просмотр результатов. |
| Результат поиска | Набор найденных проездов/сработок по параметрам поискового запроса. |
| Проезд / событие / сработка | Факт фиксации ТС устройством контроля в определенные дату, время и место. |
| Журнал проездов | Табличное представление результатов поиска. |
| Карта | Географическое представление результатов в виде маркеров, кластеров, маршрутов и типовых точек. |
| Маркер | Объект на карте, соответствующий одному событию с координатами. |
| Кластер | Объект на карте, объединяющий несколько близко расположенных событий. |
| Карточка сработки | Детальное представление одного события с атрибутами, фотоматериалами и действиями. |
| Краткая карточка события | Элемент боковой панели с основными данными по событию. |
| Боковая панель | Правая панель экрана результатов с названием поиска, кнопками действий, фильтрами, событиями и маршрутами. |
| Плашка активного поиска | Индикатор поискового набора на карте со статусом и количеством результатов. |

| Архивная точка | Позиция архивного потока устройства, соответствующая времени фиксации события. |
| Отчет | Выгрузка результатов поиска в выбранном формате и выбранное место сохранения. |

## 2. Требования

### 2.1. Бизнес-требования

- **US.IF.10.1.** Как Пользователь, я хочу просматривать результаты поиска в разных представлениях, чтобы выбирать наиболее удобный способ анализа.
- **US.IF.10.2.** Как Пользователь, я хочу видеть маркеры и кластеры на карте, чтобы быстро оценивать географическую плотность событий.
- **US.IF.10.3.** Как Пользователь, я хочу видеть краткий список событий в боковой панели, чтобы быстро переходить к интересующим проездам.
- **US.IF.10.4.** Как Пользователь, я хочу открыть карточку сработки со всеми метаданными и фотоматериалами, чтобы подробно изучить материал.
- **US.IF.10.5.** Как Пользователь, я хочу фильтровать и сортировать результаты по атрибутам ТС и события, чтобы углубленно анализировать выдачу.
- **US.IF.10.6.** Как Пользователь, я хочу видеть маршруты ТС на карте и в боковой панели, чтобы понимать перемещение ТС.
- **US.IF.10.7.** Как Пользователь, я хочу видеть типовые точки маршрута, чтобы оценивать зоны повторяющейся фиксации.
- **US.IF.10.8.** Как Пользователь, я хочу скачать или сохранить данные по проездам, чтобы изучить их позже.
- **US.IF.10.9.** Как Пользователь, я хочу просматривать результаты нескольких поисков на карте, чтобы находить пересечения разных поисковых наборов.
- **US.IF.10.10.** Как Пользователь, я хочу быстро открыть форму отчета из экрана результатов, чтобы сформировать выгрузку без ухода с текущего контекста.
- **US.IF.10.11.** Как Пользователь, я хочу получать перечень двойников по заданному ТС, чтобы эффективнее проводить оперативно-разыскные мероприятия. Требование на будущее.
- **US.IF.10.12.** Как Пользователь, я хочу получать перечень машин сопровождения ТС с учетом временного лага, чтобы расширить варианты поиска. Требование на будущее.

### 2.2. Функциональные требования

#### 2.2.1. Запуск просмотра результатов и возврат к поиску

- **FR.IF.10.1.1.** После успешного выполнения поиска система должна давать Пользователю возможность открыть результаты поиска.
- **FR.IF.10.1.2.** При открытии результатов система должна отобразить события выбранного поиска на карте.
- **FR.IF.10.1.3.** Если результаты поиска уже открыты, действие открытия должно заменяться действием скрытия результатов.
- **FR.IF.10.1.4.** При скрытии последнего активного поискового набора система должна убрать маркеры, кластеры, маршруты, типовые точки и боковую панель результатов.
- **FR.IF.10.1.5.** При открытии результатов система должна назначить поисковому набору отдельный цветовой индикатор.
- **FR.IF.10.1.6.** Назначенный цвет должен использоваться для маркеров, кластеров, плашек активного поиска, элементов легенды и кратких карточек событий этого поискового набора.
- **FR.IF.10.1.7.** Пользователь должен иметь возможность открыть карточку события из списка результатов, маркера, кластера или боковой панели.
- **FR.IF.10.1.8.** Пользователь должен иметь возможность вернуться из карточки события к списку результатов с сохранением позиции списка, фильтров, сортировки и выбранного поискового набора.

#### 2.2.2. Компоновка экрана результатов

- **FR.IF.10.2.1.** Экран результатов должен состоять из области карты и боковой панели.
- **FR.IF.10.2.2.** Над картой должна отображаться компактная плашка навигации с элементами "Поиск...", "Тэг", "Иерархия", "Управляемое".
- **FR.IF.10.2.3.** Плашка навигации карты должна располагаться вне контейнера карты, не перекрывать карту и быть визуально компактнее полноширинной панели.
- **FR.IF.10.2.4.** На карте должны отображаться плашки активных поисков со статусом выполнения и количеством найденных событий.
- **FR.IF.10.2.5.** Боковая панель должна отображать наименование активного поиска, статус, количество проездов и количество маршрутов.
- **FR.IF.10.2.6.** В верхней части боковой панели кнопка "Отчеты" должна располагаться над кнопкой "Фильтры".
- **FR.IF.10.2.7.** Кнопки "Отчеты" и "Фильтры" должны иметь одинаковую ширину.
- **FR.IF.10.2.8.** При адаптивном отображении плашка навигации карты, карта и боковая панель должны сохранять читаемость и не перекрывать друг друга.

#### 2.2.3. Представления результатов

- **FR.IF.10.3.1.** На экране результатов Пользователю должны быть доступны представления "События" и "Маршруты".
- **FR.IF.10.3.2.** Если в продуктовой конфигурации доступен журнал проездов, он должен открываться без повторного запуска поиска.
- **FR.IF.10.3.3.** Переключение между представлениями не должно запускать новый поиск.
- **FR.IF.10.3.4.** При переключении между представлениями система должна сохранять текущий набор результатов, примененные фильтры, сортировку, масштаб и центр карты.
- **FR.IF.10.3.5.** Если результатов поиска нет, система должна показать пустое состояние с текстом "По заданным параметрам результатов не найдено".
- **FR.IF.10.3.6.** Если к результатам применены фильтры, система должна отображать признак примененных фильтров в доступных представлениях.

#### 2.2.4. Фильтрация результатов

- **FR.IF.10.4.1.** Боковая панель должна предоставлять кнопку "Фильтры", открывающую панель фильтрации.
- **FR.IF.10.4.2.** Кнопка "Фильтры" должна отображать количество доступных или активных фильтров.
- **FR.IF.10.4.3.** Панель фильтрации должна содержать поле периода времени.
- **FR.IF.10.4.4.** После периода времени фильтры атрибутов ТС должны отображаться в следующем порядке: "Тип ТС", "Марка", "Модель", "Цвет".
- **FR.IF.10.4.5.** После основных атрибутов ТС должны отображаться дополнительные фильтры "Страна" и "Тип номера".
- **FR.IF.10.4.6.** Фильтр "Тип кузова" не должен отображаться в текущем UI.
- **FR.IF.10.4.7.** В панели фильтрации не должно быть отдельного чекбокса "применять".
- **FR.IF.10.4.8.** Для применения выбранных фильтров Пользователю должна быть доступна кнопка "Показать результаты".
- **FR.IF.10.4.9.** Пользователь должен иметь возможность сбросить настройки фильтрации или сортировки одной командой, если такая команда доступна в текущем представлении.
- **FR.IF.10.4.10.** После сброса фильтров система должна отобразить полный набор результатов текущего поиска.
- **FR.IF.10.4.11.** Если фильтры не дали результатов, система должна показать пустое состояние и предложить сбросить фильтры.

#### 2.2.5. Сортировка результатов

- **FR.IF.10.5.1.** По умолчанию список событий должен группироваться и сортироваться по дате и времени фиксации от новых событий к старым.
- **FR.IF.10.5.2.** Для каждого фильтруемого элемента, кроме даты и времени, должна быть доступна кнопка сортировки.
- **FR.IF.10.5.3.** Для поля периода времени кнопка сортировки не отображается.
- **FR.IF.10.5.4.** Одновременно может быть активна только одна сортировка.
- **FR.IF.10.5.5.** При включении сортировки по одному элементу система должна отключать ранее активную сортировку по другому элементу.
- **FR.IF.10.5.6.** Активная сортировка должна иметь визуальное выделение.
- **FR.IF.10.5.7.** При выборе сортировки список событий должен группироваться по названию выбранного параметра сортировки.
- **FR.IF.10.5.8.** Заголовок группы событий должен отображать название параметра сортировки и значение группы.
- **FR.IF.10.5.9.** При сбросе сортировки система должна вернуть группировку списка событий по дате.
- **FR.IF.10.5.10.** Сортировка должна применяться к текущему набору результатов с учетом активных фильтров.

#### 2.2.6. Список событий в боковой панели

- **FR.IF.10.6.1.** В представлении "События" боковая панель должна отображать краткие карточки событий.
- **FR.IF.10.6.2.** Краткая карточка события должна содержать тип события, место фиксации, время фиксации и основные атрибуты ТС.
- **FR.IF.10.6.3.** Если список сгруппирован по дате, заголовок группы должен отображать дату.
- **FR.IF.10.6.4.** Если список сгруппирован по сортируемому атрибуту, заголовок группы должен отображать название атрибута и его значение.
- **FR.IF.10.6.5.** При выборе краткой карточки система должна иметь возможность открыть карточку события.
- **FR.IF.10.6.6.** Если значение атрибута отсутствует, система должна отображать предметное состояние: "Нет данных", "Нет координат", "Нет фото" или аналогичное.
- **FR.IF.10.6.7.** При большом количестве событий боковая панель должна использовать ленивую загрузку или виртуализацию.

#### 2.2.7. Действия со строкой журнала или карточкой события

- **FR.IF.10.7.1.** Для каждой строки журнала или карточки события должно быть доступно действие "Открыть карточку сработки".
- **FR.IF.10.7.2.** Для события с координатами должно быть доступно действие "Показать на карте". Требование на будущее.
- **FR.IF.10.7.3.** Для события с доступной архивной точкой должно быть доступно действие "Перейти к архиву".
- **FR.IF.10.7.4.** Для события с фотоматериалами должно быть доступно действие "Открыть фото".

#### 2.2.8. Карта результатов

- **FR.IF.10.8.1.** Карта должна отображать события, выбранные по результатам поиска.
- **FR.IF.10.8.2.** Карта должна поддерживать режим "События".
- **FR.IF.10.8.3.** Карта должна поддерживать режим "Маршруты".
- **FR.IF.10.8.4.** Карта должна поддерживать режим "Типовые точки", если он доступен в текущей конфигурации.
- **FR.IF.10.8.5.** Карта должна поддерживать просмотр нескольких поисков, если на карту добавлены результаты более одного поиска.
- **FR.IF.10.8.6.** При включении режима "События" система должна отображать отдельные маркеры и кластеры.
- **FR.IF.10.8.7.** При включении режима "Маршруты" система должна отображать линии маршрутов, точки фиксации и временные метки.
- **FR.IF.10.8.8.** При включении режима "Типовые точки" система должна отображать все типовые точки за период поиска и выделять наиболее частые точки.
- **FR.IF.10.8.9.** Пользователь должен иметь возможность выбрать только один режим представления карты в рамках одного активного отображения.

#### 2.2.9. Маркеры событий и кластеры

- **FR.IF.10.9.1.** Один маркер на карте должен соответствовать одному событию с координатами.
- **FR.IF.10.9.2.** При клике по маркеру система должна открыть всплывающую краткую карточку события.
- **FR.IF.10.9.3.** Всплывающая карточка маркера должна содержать дату и время фиксации, номер ТС, устройство или камеру, место фиксации и доступные действия.
- **FR.IF.10.9.4.** Система должна объединять события в кластер, если несколько событий имеют одинаковые или близкие координаты.
- **FR.IF.10.9.5.** Кластер должен отображать количество входящих событий.
- **FR.IF.10.9.6.** Если отображается несколько поисков, кластер должен различать доли или принадлежность событий к поисковым наборам, если такие данные доступны.
- **FR.IF.10.9.7.** При изменении масштаба или области карты система должна пересчитывать состав кластеров.
- **FR.IF.10.9.8.** При клике по кластеру система должна открыть список событий кластера, если события остаются в одной точке или дальнейшее приближение невозможно.
- **FR.IF.10.9.9.** Если карта отображает отфильтрованный набор результатов, кластеризация должна выполняться только по событиям этого набора.
- **FR.IF.10.9.10.** Если одно событие входит в несколько отображаемых поисков, система должна отображать его как один объект и относить к первому активному поиску по правилу продукта.

#### 2.2.10. Маршруты ТС

- **FR.IF.10.10.1.** Маршруты должны строиться по результатам текущего поиска.
- **FR.IF.10.10.2.** Базовая группировка маршрута должна выполняться по правилу: один государственный номер ТС и одна календарная дата фиксации образуют одну маршрутную группу.
- **FR.IF.10.10.3.** События внутри маршрута должны сортироваться по времени фиксации от ранних к поздним.
- **FR.IF.10.10.4.** Маршрут должен отображаться на карте как линия, соединяющая точки фиксации в хронологическом порядке.
- **FR.IF.10.10.5.** На маршруте должны отображаться начальная точка, конечная точка, промежуточные точки и временные метки.
- **FR.IF.10.10.6.** Если несколько маршрутов отображаются одновременно, система должна различать их цветом, стилем линии или номером в легенде.
- **FR.IF.10.10.7.** В режиме "Маршруты" боковая панель должна группировать события по маршрутным группам.
- **FR.IF.10.10.8.** Заголовок маршрутной группы должен содержать номер ТС, дату маршрута, количество точек фиксации и временной диапазон маршрута.
- **FR.IF.10.10.9.** Пользователь должен иметь возможность свернуть и развернуть маршрутную группу.
- **FR.IF.10.10.10.** При выборе маршрута в боковой панели система должна выделять соответствующую линию на карте.
- **FR.IF.10.10.11.** При выборе события внутри маршрутной группы система должна выделять соответствующую точку маршрута.

#### 2.2.11. Типовые точки маршрута

- **FR.IF.10.11.1.** Режим "Типовые точки" должен отображать все точки фиксации за период текущего поиска.
- **FR.IF.10.11.2.** Для расчета типовой точки система должна использовать нормализацию по идентификатору устройства и камеры, если они доступны.
- **FR.IF.10.11.3.** Если идентификатор устройства или камеры отсутствует, система должна использовать координаты с округлением до 5 знаков после запятой.
- **FR.IF.10.11.4.** Если координаты и идентификаторы отсутствуют, событие не участвует в расчете типовых точек.
- **FR.IF.10.11.5.** Для каждой типовой точки система должна рассчитывать количество связанных фиксаций.
- **FR.IF.10.11.6.** Система должна сортировать типовые точки по количеству фиксаций по убыванию.
- **FR.IF.10.11.7.** Система должна выделять особым цветом 5% типовых точек с максимальным количеством фиксаций.
- **FR.IF.10.11.8.** Количество выделяемых типовых точек должно рассчитываться с округлением вверх.
- **FR.IF.10.11.9.** Если в наборе есть хотя бы одна типовая точка, система должна выделить минимум одну наиболее частую точку.
- **FR.IF.10.11.10.** При равном количестве фиксаций на границе топ-5% система должна применять вторичное правило сортировки: более ранняя первая фиксация, затем идентификатор точки по возрастанию.
- **FR.IF.10.11.11.** Каждая типовая точка должна раскрываться в перечень включенных в нее проездов.

#### 2.2.12. Карточка сработки, фото и архив

- **FR.IF.10.12.1.** Карточка сработки должна открываться из строки журнала, маркера на карте, списка событий кластера, краткой карточки боковой панели, точки маршрута или типовой точки.
- **FR.IF.10.12.2.** Карточка сработки должна содержать метаданные события и доступные фотоматериалы.
- **FR.IF.10.12.3.** В карточке сработки должны быть доступны действия: показать событие на карте, перейти к архивной точке, открыть фото в увеличенном виде, вернуться к списку результатов.
- **FR.IF.10.12.4.** Если часть данных карточки недоступна, система должна отображать причину: нет данных, нет фото, архивный поток недоступен или нет прав.
- **FR.IF.10.12.5.** Карточка сработки должна отображать обзорное фото и фото номера, если они доступны.
- **FR.IF.10.12.6.** Пользователь должен иметь возможность открыть изображение в увеличенном виде.
- **FR.IF.10.12.7.** Если фото отсутствует, система должна показать состояние "Фото отсутствует".
- **FR.IF.10.12.8.** Переход к архивной точке должен открывать архивный поток устройства на момент фиксации события.
- **FR.IF.10.12.9.** Если архивная точка недоступна, система должна показать причину: архив не найден, истек срок хранения, нет прав на просмотр архива или устройство недоступно.

#### 2.2.13. Отчеты

- **FR.IF.10.13.1.** В боковой панели должна быть доступна кнопка "Отчеты".
- **FR.IF.10.13.2.** Кнопка "Отчеты" должна располагаться над кнопкой "Фильтры" и иметь с ней одинаковую ширину.
- **FR.IF.10.13.3.** При нажатии кнопки "Отчеты" система должна открыть форму настройки отчета.
- **FR.IF.10.13.4.** Форма отчета должна содержать поле "Наименование отчета".
- **FR.IF.10.13.5.** По умолчанию наименование отчета должно формироваться как "Отчет <наименование поиска>".
- **FR.IF.10.13.6.** Пользователь должен иметь возможность изменить наименование отчета.
- **FR.IF.10.13.7.** Форма отчета должна содержать выбор типа файла: Excel, Word или PDF.
- **FR.IF.10.13.8.** Форма отчета должна содержать выбор места сохранения: "В Личный кабинет" или "На устройство".
- **FR.IF.10.13.9.** В форме отчета должны быть доступны действия отмены и формирования отчета.
- **FR.IF.10.13.10.** Подробный состав данных отчета, правила генерации файла и доставка результата описываются в отдельном разделе по отчетам.

#### 2.2.14. Просмотр результатов нескольких поисков

- **FR.IF.10.14.1.** Пользователь должен иметь возможность добавить на карту результаты нескольких поисков.
- **FR.IF.10.14.2.** Для каждого добавленного поиска система должна автоматически подбирать отдельный цветовой индикатор.
- **FR.IF.10.14.3.** Пользователь должен иметь возможность включать и выключать отображение каждого поискового слоя.
- **FR.IF.10.14.4.** Система должна поддерживать одновременное отображение не более 10 результатов поиска.
- **FR.IF.10.14.5.** При добавлении поиска сверх лимита система должна скрыть первый поисковый набор в списке активных наборов.
- **FR.IF.10.14.6.** Кластеры должны рассчитываться по всем выбранным поискам.
- **FR.IF.10.14.7.** При просмотре результатов нескольких поисков боковая панель должна отображать события по всем активным поискам и различать их цветовыми индикаторами.
- **FR.IF.10.14.8.** Если одно и то же событие входит в несколько поисков, система должна относить событие к первому активному поиску.
- **FR.IF.10.14.9.** После удаления последнего активного поискового слоя система должна возвращать карту к обычному представлению камер.

### 2.3. Нефункциональные требования

#### 2.3.1. Производительность

- **NFR.IF.10.1.1.** Для поисковой выдачи до 1000 событий список или журнал должен отображать первую страницу результатов не дольше чем за 2 секунды после получения данных от сервера.
- **NFR.IF.10.1.2.** Переключение между представлениями без изменения параметров поиска должно занимать не более 1 секунды для уже загруженного набора до 10000 событий.
- **NFR.IF.10.1.3.** Первичная отрисовка маркеров и кластеров на карте для набора до 10000 событий с координатами должна занимать не более 3 секунд после получения данных.
- **NFR.IF.10.1.4.** Открытие карточки сработки должно занимать не более 2 секунд для 95% запросов при нормальной доступности сервисов данных.
- **NFR.IF.10.1.5.** Построение маршрутов для набора до 10000 событий должно занимать не более 5 секунд после получения данных.
- **NFR.IF.10.1.6.** Расчет типовых точек для набора до 10000 событий должен занимать не более 5 секунд после получения данных.

#### 2.3.2. Масштабируемость

- **NFR.IF.10.2.1.** Архитектура должна поддерживать отображение результатов поиска объемом не менее 100000 событий через серверную пагинацию, агрегацию, кластеризацию или ленивую загрузку.
- **NFR.IF.10.2.2.** Карта не должна пытаться одновременно отрисовывать более 5000 отдельных маркеров в видимой области без кластеризации или агрегации.
- **NFR.IF.10.2.3.** Боковая панель должна использовать ленивую загрузку или виртуализацию при количестве карточек больше 100.

#### 2.3.3. Надежность и устойчивость к ошибкам

- **NFR.IF.10.3.1.** Ошибка загрузки карты не должна блокировать просмотр списка или журнала.
- **NFR.IF.10.3.2.** Ошибка загрузки фото не должна блокировать просмотр метаданных карточки сработки.
- **NFR.IF.10.3.3.** Ошибка открытия архивной точки не должна приводить к потере текущего контекста результатов поиска.
- **NFR.IF.10.3.4.** При временной ошибке загрузки карточки, фото, карты или архива система должна предлагать повторить действие.
- **NFR.IF.10.3.5.** Если часть событий повреждена или содержит неполные данные, система должна отображать корректные события и предметные статусы для неполных событий.
- **NFR.IF.10.3.6.** Состояние выбранного события, фильтров, сортировки и режима карты должно сохраняться при обновлении данных внутри текущей сессии.

#### 2.3.4. Безопасность и разграничение доступа

- **NFR.IF.10.4.1.** Все результаты, фотоматериалы, архивные потоки и отчеты должны отображаться только с учетом прав Пользователя.
- **NFR.IF.10.4.2.** Если Пользователь не имеет права на устройство, событие с этого устройства не должно отображаться в результатах.
- **NFR.IF.10.4.3.** Если Пользователь не имеет права на архив, действие перехода к архивной точке должно быть недоступно.
- **NFR.IF.10.4.4.** Если Пользователь не имеет права формировать отчеты, кнопка "Отчеты" должна быть скрыта или недоступна согласно правилам продукта.

#### 2.3.5. Консистентность данных

- **NFR.IF.10.5.1.** Список событий, журнал, карта, боковая панель, карточка сработки и отчет должны использовать один и тот же идентификатор события.
- **NFR.IF.10.5.2.** Время фиксации должно отображаться в едином часовом поясе, заданном настройками системы или профиля Пользователя.
- **NFR.IF.10.5.3.** Фильтры и сортировка должны применяться к одному и тому же текущему набору результатов во всех представлениях.

| Поле | Описание |
| --- | --- |
| Название | UC.IF.10.6. Просмотр нескольких поисков на карте |
| Актор | Пользователь платформы |
| Предусловия | Пользователь выполнил два или более поиска. |
| Постусловия | На карте отображаются результаты нескольких поисков, каждый поисковый набор имеет отдельный цветовой индикатор. |
| Основной сценарий | 1. Пользователь открывает первый поисковый набор.<br>2. Система отображает первый набор согласно UC.IF.10.1.<br>3. Пользователь открывает второй поисковый набор.<br>4. Система назначает второму набору другой цветовой индикатор.<br>5. Система отображает маркеры и кластеры по всем активным поисковым наборам.<br>6. Система отображает события по всем активным поискам в боковой панели и различает их цветовыми индикаторами.<br>7. Пользователь скрывает один из поисковых наборов.<br>8. Система убирает его события с карты и из боковой панели. |
| Альтернативный сценарий. Превышен лимит активных поисков | 1. Система определяет, что количество активных поисковых наборов превышает лимит 10.<br>2. Система скрывает первый поисковый набор в списке активных наборов.<br>3. Система отображает новый поисковый набор с отдельным цветовым индикатором. |

### 3.7. UC.IF.10.7. Анализ типовых точек маршрута

Требование на будущее.

| Поле | Описание |
| --- | --- |
| Название | UC.IF.10.7. Анализ типовых точек маршрута |
| Актор | Пользователь платформы |
| Предусловия | Пользователь открыл результаты поиска. В результатах есть события с координатами или идентификаторами устройств/камер для расчета типовых точек. |

Система выделяет 5% точек с максимальным количеством фиксаций.<br>6. Пользователь выбирает типовую точку.<br>7. Система показывает количество фиксаций, список связанных событий и распределение по датам, если данные доступны. |
