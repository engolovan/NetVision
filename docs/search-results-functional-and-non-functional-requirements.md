# NetVision. Результаты поиска: функциональные и нефункциональные требования

## 1. Назначение документа

Документ конкретизирует бизнес-требования US.IF.10.x к просмотру и анализу результатов поиска проездов ТС в системе NetVision.

Требования сформулированы так, чтобы их можно было использовать для:

- декомпозиции задач разработки;
- проектирования интерфейсов и API;
- подготовки тест-кейсов;
- приемки результата.

## 2. Область применения

### 2.1. В текущий функциональный контур входят

- просмотр результатов поиска в журнале проездов;
- просмотр результатов поиска на карте;
- переключение между журналом и картой без повторного запуска поиска;
- отображение маркеров, кластеров, маршрутов и типовых точек на карте;
- раскрытие кластеров и просмотр входящих событий;
- боковая панель с краткими карточками событий;
- карточка сработки с метаданными и фотоматериалами;
- фильтрация и сортировка журнала проездов;
- отображение маршрутов ТС, сгруппированных по дате и номеру ТС;
- отображение типовых точек маршрута с выделением 5% наиболее частых точек;
- переход от события к архивной точке, если архив доступен;
- просмотр результатов нескольких поисков на одной карте;
- выгрузка и/или сохранение данных по проездам, если модуль отчетов включен в релиз.

### 2.2. Будущий функциональный контур

Следующие возможности должны учитываться при проектировании интерфейса и модели данных, но могут поставляться отдельными релизами:

- перечень двойников по заданному ТС;
- перечень машин сопровождения ТС с учетом временного лага;
- расширенная отчетность: PDF, Excel, DOCX, сохранение отчета в личном кабинете.

## 3. Термины

| Термин | Определение |
| --- | --- |
| Пользователь | Авторизованный пользователь NetVision, имеющий права на поиск и просмотр результатов. |
| Результат поиска | Набор найденных проездов/сработок по параметрам поискового запроса. |
| Проезд / событие / сработка | Факт фиксации ТС устройством контроля в определенные дату, время и место. |
| Журнал проездов | Табличное представление результатов поиска. |
| Карта | Географическое представление результатов в виде маркеров, кластеров, маршрутов и типовых точек. |
| Маркер | Объект на карте, соответствующий одному событию с координатами. |
| Кластер | Объект на карте, объединяющий несколько близко расположенных событий. |
| Карточка сработки | Детальное представление одного события с атрибутами, фотоматериалами и действиями. |
| Краткая карточка события | Элемент боковой панели с основными данными по событию. |
| Маршрут | Последовательность событий одного номера ТС за одну дату или иной настроенный период группировки. |
| Типовая точка | Точка или нормализованная зона фиксации, используемая для анализа повторяемости. |
| Архивная точка | Позиция архивного потока устройства, соответствующая времени фиксации события. |

## 4. Функциональные требования

### 4.1. Запуск просмотра результатов и возврат к поиску

**FR-IF-10-000.** После выполнения поиска система должна показывать Пользователю действие "Посмотреть" для перехода к просмотру найденных результатов.

**FR-IF-10-000.1.** При выборе действия "Посмотреть" система должна открыть результаты выбранного поиска в режиме просмотра результатов.

**FR-IF-10-000.2.** При открытии результатов через действие "Посмотреть" система должна автоматически отобразить события поиска на карте, если у событий есть координаты.

**FR-IF-10-000.3.** При открытии результатов через действие "Посмотреть" система должна назначить поисковому набору отдельный цвет маркеров автоматически.

**FR-IF-10-000.4.** Назначенный цвет должен использоваться для маркеров, кластеров, элементов легенды и кратких карточек событий этого поискового набора.

**FR-IF-10-000.5.** Пользователь должен иметь возможность перейти от просмотра результатов к списку событий текущего поиска.

**FR-IF-10-000.6.** Пользователь должен иметь возможность открыть карточку конкретного события из списка результатов, маркера, кластера или боковой панели.

**FR-IF-10-000.7.** Пользователь должен иметь возможность вернуться из карточки события к списку результатов с сохранением текущей позиции списка, фильтров, сортировки и выбранного поискового набора.

**FR-IF-10-000.8.** Пользователь должен иметь возможность вернуться из просмотра результатов к поиску через действие "Назад к поиску" или эквивалентное действие интерфейса.

**FR-IF-10-000.9.** При возврате к поиску система должна сохранять параметры последнего поискового запроса, чтобы Пользователь мог изменить их и запустить поиск повторно.

**FR-IF-10-000.10.** Пользователь должен иметь возможность закрыть отображение результатов отдельного поиска на карте без удаления самого поиска из истории или результатов.

**FR-IF-10-000.11.** Если Пользователь закрыл все активные поисковые наборы на карте, система должна убрать маркеры, кластеры, маршруты, типовые точки и боковую панель результатов и вернуться к обычному представлению камер.

**FR-IF-10-000.12.** В обычном представлении камер карта должна отображать камеры и другие стандартные слои согласно настройкам продукта, без визуальных элементов результатов поиска.

### 4.2. Единый экран результатов поиска

**FR-IF-10-001.** Система должна открывать результаты поиска на едином экране результатов после успешного выполнения поискового запроса.

**FR-IF-10-002.** На экране результатов Пользователю должны быть доступны как минимум два представления:

- "Журнал";
- "Карта".

**FR-IF-10-003.** Система должна отображать параметры исходного поискового запроса на экране результатов: временной диапазон, искомый номер/номера ТС, устройства/зоны поиска и другие примененные параметры, если они были заданы.

**FR-IF-10-004.** Переключение между журналом и картой не должно запускать новый поиск, если Пользователь не изменил параметры исходного поискового запроса.

**FR-IF-10-005.** При переключении между представлениями система должна сохранять:

- текущий набор результатов;
- выбранное событие;
- примененные фильтры журнала;
- сортировку журнала;
- текущий масштаб и центр карты;
- выбранный режим карты, если он применим к текущему набору данных.

**FR-IF-10-006.** Если результатов поиска нет, система должна показать пустое состояние в журнале и на карте с текстом "По заданным параметрам результатов не найдено" и возможностью вернуться к параметрам поиска.

### 4.3. Синхронизация представлений

**FR-IF-10-010.** При выборе строки в журнале система должна выделять соответствующее событие в боковой панели и на карте, если у события есть координаты.

**FR-IF-10-011.** При выборе маркера на карте система должна выделять соответствующую краткую карточку в боковой панели.

**FR-IF-10-012.** При выборе краткой карточки в боковой панели система должна центрировать карту на событии, если у события есть координаты.

**FR-IF-10-013.** Если выбранное событие не имеет координат, система должна оставить выбор события в журнале/боковой панели и показать признак "Нет координат" вместо попытки центрирования карты.

**FR-IF-10-014.** Если журнал и карта открыты в разных режимах одного экрана, идентификатор выбранного события должен быть единым для всех представлений.

### 4.4. Журнал проездов

**FR-IF-10-020.** Журнал должен отображать результаты поиска в виде таблицы.

**FR-IF-10-021.** Каждая строка журнала должна соответствовать одному событию.

**FR-IF-10-022.** Минимальный набор колонок журнала должен включать:

- дату и время фиксации;
- государственный регистрационный номер ТС;
- регион номера;
- марку ТС, если определена;
- модель ТС, если определена;
- цвет ТС, если определен;
- тип ТС, если определен;
- направление движения, если определено;
- устройство фиксации;
- камеру/канал фиксации, если применимо;
- адрес или описание места фиксации;
- координаты фиксации;
- статус/качество распознавания номера;
- источник события;
- признак наличия фотоматериалов;
- признак наличия архивной точки;
- действие "Открыть карточку";
- действие "Показать на карте";
- действие "Перейти к архиву", если архив доступен.

**FR-IF-10-023.** Если значение атрибута отсутствует, в ячейке должно отображаться значение "Нет данных", "Нет координат", "Нет фото" или другое предметное состояние, а не пустая ячейка.

**FR-IF-10-024.** Журнал должен поддерживать постраничную загрузку или виртуализацию строк при количестве результатов больше 1000.

**FR-IF-10-025.** Пользователь должен иметь возможность изменить видимость колонок журнала, если такая настройка поддерживается продуктом.

**FR-IF-10-026.** Система должна сохранять выбранные Пользователем настройки колонок в рамках пользовательской сессии.

### 4.5. Фильтрация журнала

**FR-IF-10-030.** Фильтрация должна применяться к уже полученному набору результатов и не должна менять исходный поисковый запрос.

**FR-IF-10-031.** Фильтрация должна быть доступна только в журнальном представлении.

**FR-IF-10-032.** Журнал должен поддерживать фильтры по времени фиксации:

- дата;
- период дат;
- точное время;
- диапазон времени внутри суток.

**FR-IF-10-033.** Журнал должен поддерживать фильтры по ТС:

- государственный номер;
- регион номера;
- марка;
- модель;
- цвет;
- тип ТС.

**FR-IF-10-034.** Журнал должен поддерживать фильтры по месту фиксации:

- устройство;
- камера/канал;
- адрес;
- район/зона;
- наличие координат;
- прямоугольная область координат, если такая область передана из карты.

**FR-IF-10-035.** Журнал должен поддерживать фильтры по событию:

- наличие фото;
- качество/уверенность распознавания;
- источник события;
- тип сработки;
- наличие архивной точки;
- доступность архивного потока.

**FR-IF-10-036.** Журнал должен поддерживать фильтры по маршрутным признакам:

- номер маршрутной группы;
- дата маршрута;
- номер ТС маршрута;
- порядковый номер точки в маршруте.

**FR-IF-10-037.** Пользователь должен иметь возможность сбросить все фильтры одной командой.

**FR-IF-10-038.** После сброса фильтров система должна отобразить полный набор результатов текущего поиска.

**FR-IF-10-039.** Если фильтры не дают совпадений, система должна показать пустое состояние отфильтрованного набора и кнопку "Сбросить фильтры".

**FR-IF-10-040.** Если карта настроена на отображение отфильтрованного набора, изменение фильтров журнала должно обновлять маркеры, кластеры, маршруты и типовые точки на карте.

### 4.6. Сортировка журнала

**FR-IF-10-050.** Журнал должен поддерживать сортировку по следующим атрибутам:

- дата и время фиксации;
- государственный номер ТС;
- регион номера;
- устройство;
- камера/канал;
- адрес/место фиксации;
- направление движения;
- качество/уверенность распознавания;
- наличие фотоматериалов;
- наличие архивной точки;
- маршрутная группа.

**FR-IF-10-051.** Для каждой сортируемой колонки Пользователь должен иметь возможность выбрать направление сортировки: по возрастанию или по убыванию.

**FR-IF-10-052.** По умолчанию журнал должен сортироваться по дате и времени фиксации.

**FR-IF-10-053.** Для режима оперативного просмотра сортировка по умолчанию должна быть от новых событий к старым.

**FR-IF-10-054.** Для режима маршрутного анализа сортировка по умолчанию должна быть от ранних событий к поздним.

**FR-IF-10-055.** При переключении между журналом и картой выбранная сортировка журнала должна сохраняться.

### 4.7. Действия со строкой журнала

**FR-IF-10-060.** Для каждой строки журнала должно быть доступно действие "Открыть карточку сработки".

**FR-IF-10-061.** Для каждой строки журнала с координатами должно быть доступно действие "Показать на карте".

**FR-IF-10-062.** Для каждой строки журнала с доступной архивной точкой должно быть доступно действие "Перейти к архиву".

**FR-IF-10-063.** Для каждой строки журнала с фотоматериалами должно быть доступно действие "Открыть фото".

**FR-IF-10-064.** Если действие недоступно из-за отсутствия данных или прав, система должна показать недоступное состояние с пояснением причины.

### 4.8. Карта результатов

**FR-IF-10-070.** Карта должна отображать события, у которых есть валидные координаты.

**FR-IF-10-071.** События без координат не должны отображаться на карте, но должны оставаться доступными в журнале и боковой панели.

**FR-IF-10-072.** Карта должна поддерживать режимы:

- "События";
- "Маршруты";
- "Типовые точки";
- "Несколько поисков", если на карту добавлены результаты более одного поиска.

**FR-IF-10-073.** При включении режима "События" система должна отображать отдельные маркеры и кластеры.

**FR-IF-10-074.** При включении режима "Маршруты" система должна отображать линии маршрутов, точки фиксации, направление движения и временные метки.

**FR-IF-10-075.** При включении режима "Типовые точки" система должна отображать все типовые точки за период поиска и выделять 5% наиболее частых точек.

**FR-IF-10-076.** Если выбранные режимы карты визуально конфликтуют, система должна отображать слой активного режима поверх остальных слоев.

**FR-IF-10-077.** Пользователь должен иметь возможность включать и выключать слои карты, если одновременно отображаются события, маршруты, типовые точки или несколько поисков.

**FR-IF-10-078.** При ошибке загрузки картографической подложки система должна сохранить доступность журнала и показать сообщение "Карта временно недоступна".

### 4.9. Маркеры событий

**FR-IF-10-080.** Один маркер на карте должен соответствовать одному событию.

**FR-IF-10-081.** Маркер должен визуально показывать местоположение события.

**FR-IF-10-082.** Если у события есть направление движения, маркер должен отображать направление или предоставлять его во всплывающей карточке.

**FR-IF-10-083.** При клике по маркеру система должна открыть всплывающую краткую карточку события.

**FR-IF-10-084.** Всплывающая карточка маркера должна содержать:

- дату и время фиксации;
- номер ТС;
- устройство/камеру;
- место фиксации;
- направление движения, если доступно;
- миниатюру фото, если доступна;
- действия "Открыть карточку", "Перейти к архиву" и "Показать в списке", если применимо.

**FR-IF-10-085.** При выборе маркера система должна выделить соответствующую карточку в боковой панели.

### 4.10. Кластеризация событий

**FR-IF-10-090.** Система должна объединять события в кластер, если на текущем масштабе карты маркеры визуально пересекаются или находятся ближе минимального расстояния, заданного настройкой кластеризации.

**FR-IF-10-091.** Система должна объединять события в кластер, если несколько событий имеют одинаковые или практически совпадающие координаты.

**FR-IF-10-092.** Координаты должны считаться практически совпадающими, если расстояние между точками меньше или равно 10 метрам, если продуктовой настройкой не задано другое значение.

**FR-IF-10-093.** Кластер должен отображать количество входящих событий.

**FR-IF-10-094.** Внешний вид кластера должен различаться по диапазонам количества событий:

- 2-9 событий;
- 10-99 событий;
- 100 и более событий.

**FR-IF-10-095.** При изменении масштаба или области карты система должна пересчитывать состав кластеров.

**FR-IF-10-096.** При клике по кластеру система должна выполнить одно из действий:

- приблизить карту к области кластера, если события можно разделить масштабированием;
- открыть список событий кластера, если события остаются в одной точке или дальнейшее приближение невозможно.

**FR-IF-10-097.** Список событий кластера должен содержать те же ключевые поля, что и краткая карточка боковой панели.

**FR-IF-10-098.** Пользователь должен иметь возможность открыть карточку сработки для любого события из списка кластера.

**FR-IF-10-099.** Если карта отображает отфильтрованный набор результатов, кластеризация должна выполняться только по событиям этого набора.

### 4.11. Боковая панель событий

**FR-IF-10-110.** В картографическом представлении система должна отображать боковую панель со списком кратких карточек событий.

**FR-IF-10-111.** Боковая панель должна поддерживать состояния:

- развернута;
- свернута;
- пустой список результатов;
- нет событий в текущей видимой области карты;
- ошибка загрузки списка.

**FR-IF-10-112.** Краткая карточка события должна содержать:

- дату и время фиксации;
- государственный номер ТС;
- устройство/камеру;
- место фиксации;
- направление движения, если доступно;
- миниатюру фото, если доступна;
- признак наличия полной карточки;
- признак наличия архивной точки;
- признак отсутствия координат, если координаты отсутствуют.

**FR-IF-10-113.** Пользователь должен иметь возможность свернуть и развернуть боковую панель.

**FR-IF-10-114.** При выборе краткой карточки система должна выделять соответствующий маркер или точку маршрута на карте.

**FR-IF-10-115.** Если карточка относится к событию без координат, система должна показать уведомление "У события нет координат для отображения на карте".

**FR-IF-10-116.** Если включен режим "Маршруты", боковая панель должна группировать события по маршрутам.

### 4.12. Карточка сработки

**FR-IF-10-120.** Карточка сработки должна открываться из:

- строки журнала;
- маркера на карте;
- списка событий кластера;
- краткой карточки боковой панели;
- точки маршрута;
- типовой точки, если событие входит в ее список.

**FR-IF-10-121.** Карточка сработки должна содержать:

- идентификатор события;
- дату и время фиксации;
- государственный номер ТС;
- регион номера;
- распознанные атрибуты ТС;
- подтвержденные атрибуты ТС, если применимо;
- устройство фиксации;
- камеру/поток/канал фиксации;
- адрес или описание места;
- координаты;
- направление движения;
- качество/уверенность распознавания;
- источник события;
- связь с маршрутом, если событие входит в маршрут;
- фотоматериалы;
- доступные действия.

**FR-IF-10-122.** В карточке сработки должны быть доступны действия:

- показать событие на карте;
- перейти к архивной точке;
- открыть фото в увеличенном виде;
- вернуться к списку результатов.

**FR-IF-10-123.** Если часть данных карточки недоступна, система должна отображать причину:

- нет данных;
- нет фото;
- нет координат;
- нет прав;
- событие удалено;
- архивный поток недоступен.

**FR-IF-10-124.** При ошибке загрузки карточки система должна показать сообщение об ошибке и действие "Повторить".

### 4.13. Фотоматериалы

**FR-IF-10-130.** Карточка сработки должна отображать все доступные фотоматериалы события:

- обзорное фото;
- фото номера;
- дополнительные кадры, если они есть.

**FR-IF-10-131.** Пользователь должен иметь возможность открыть изображение в увеличенном виде.

**FR-IF-10-132.** Пользователь должен иметь возможность переключаться между доступными кадрами одного события.

**FR-IF-10-133.** Для каждого фото должна отображаться временная метка, если она хранится в системе.

**FR-IF-10-134.** Если фото отсутствует, система должна показать состояние "Фото отсутствует".

**FR-IF-10-135.** Если фото недоступно из-за прав, система должна показать состояние "Недостаточно прав для просмотра фото".

### 4.14. Маршруты ТС

**FR-IF-10-140.** Маршруты должны строиться по результатам текущего поиска.

**FR-IF-10-141.** Базовая группировка маршрута должна выполняться по правилу: один государственный номер ТС + одна календарная дата фиксации = одна маршрутная группа.

**FR-IF-10-142.** Если в продуктовых настройках задан порог разрыва маршрута, система должна разделять маршрут на несколько групп при превышении этого порога между соседними событиями одного ТС.

**FR-IF-10-143.** События внутри маршрута должны сортироваться по времени фиксации от ранних к поздним.

**FR-IF-10-144.** Маршрут должен отображаться на карте как линия, соединяющая точки фиксации в хронологическом порядке.

**FR-IF-10-145.** На маршруте должны отображаться:

- начальная точка;
- конечная точка;
- промежуточные точки;
- временные метки ключевых точек;
- направление движения;
- цвет или стиль маршрута;
- выделенное состояние выбранного маршрута.

**FR-IF-10-146.** Если несколько маршрутов отображаются одновременно, система должна различать их цветом, стилем линии или номером в легенде.

**FR-IF-10-147.** События маршрута без координат не должны включаться в линию маршрута, но должны отображаться в боковой панели маршрута с признаком "Нет координат".

**FR-IF-10-148.** При выборе маршрута в боковой панели система должна выделять соответствующую линию на карте.

**FR-IF-10-149.** При выборе точки маршрута система должна выделять точку на карте и открывать краткую информацию о событии.

### 4.15. Группировка боковой панели по маршрутам

**FR-IF-10-150.** В режиме "Маршруты" боковая панель должна группировать события по маршрутным группам.

**FR-IF-10-151.** Заголовок маршрутной группы должен содержать:

- номер ТС;
- дату маршрута;
- количество точек фиксации;
- временной диапазон маршрута;
- признак наличия событий без координат.

**FR-IF-10-152.** События внутри маршрутной группы должны отображаться в хронологическом порядке.

**FR-IF-10-153.** Пользователь должен иметь возможность свернуть и развернуть маршрутную группу.

**FR-IF-10-154.** При раскрытии группы система должна отображать список событий маршрута.

**FR-IF-10-155.** При выборе события внутри группы система должна выделять соответствующую точку маршрута или показывать состояние "Нет координат".

### 4.16. Типовые точки маршрута

**FR-IF-10-160.** Режим "Типовые точки" должен отображать все точки фиксации за период текущего поиска.

**FR-IF-10-161.** Для расчета типовой точки система должна использовать нормализацию:

- сначала по идентификатору устройства и камеры, если они есть;
- если идентификатор устройства/камеры отсутствует, по координатам с округлением до 5 знаков после запятой;
- если координаты отсутствуют, событие не участвует в расчете типовых точек.

**FR-IF-10-162.** Для каждой типовой точки система должна рассчитывать количество связанных фиксаций.

**FR-IF-10-163.** Система должна сортировать типовые точки по количеству фиксаций по убыванию.

**FR-IF-10-164.** Система должна выделять особым цветом 5% типовых точек с максимальным количеством фиксаций.

**FR-IF-10-165.** Количество выделяемых типовых точек должно рассчитываться с округлением вверх.

**FR-IF-10-166.** Если в наборе есть хотя бы одна типовая точка, система должна выделить минимум одну наиболее частую точку.

**FR-IF-10-167.** При равном количестве фиксаций на границе топ-5% система должна выделять точки по вторичному правилу сортировки: более ранняя первая фиксация, затем идентификатор точки по возрастанию.

**FR-IF-10-168.** Для каждой типовой точки Пользователь должен видеть:

- количество фиксаций;
- список связанных событий;
- распределение по датам, если данные доступны;
- действие перехода к событиям точки.

### 4.17. Переход к архивной точке

**FR-IF-10-170.** Переход к архивной точке должен быть доступен из:

- строки журнала;
- карточки сработки;
- краткой карточки боковой панели;
- всплывающей карточки маркера;
- списка событий кластера;
- точки маршрута.

**FR-IF-10-171.** Система должна открывать архивный поток устройства на момент фиксации события.

**FR-IF-10-172.** Если точный момент фиксации недоступен, система должна открывать ближайшую доступную позицию архива и показывать фактическое открытое время.

**FR-IF-10-173.** Если архивная точка недоступна, система должна показать одну из причин:

- архив не найден;
- истек срок хранения;
- нет прав на просмотр архива;
- устройство недоступно;
- поток недоступен;
- временная метка события некорректна.

**FR-IF-10-174.** Если у Пользователя нет прав на архив, действие перехода должно быть заблокировано до клика и сопровождаться пояснением.

### 4.18. Выгрузка и сохранение данных по проездам

**FR-IF-10-180.** Пользователь должен иметь возможность инициировать выгрузку данных по текущему набору проездов, если функция отчетности включена в текущем релизе.

**FR-IF-10-181.** Выгрузка должна учитывать примененные фильтры журнала, если Пользователь выбирает вариант "Выгрузить отфильтрованные".

**FR-IF-10-182.** Выгрузка должна учитывать полный набор результатов текущего поиска, если Пользователь выбирает вариант "Выгрузить все результаты поиска".

**FR-IF-10-183.** Минимальный состав выгружаемых данных должен включать поля журнала проездов и параметры исходного поискового запроса.

**FR-IF-10-184.** Если в выгрузку включаются фотоматериалы, система должна проверять права Пользователя на доступ к фото.

**FR-IF-10-185.** Если функция сохранения отчета в личном кабинете включена, Пользователь должен иметь возможность сохранить сформированный отчет с названием, датой формирования и параметрами запроса.

**FR-IF-10-186.** Если модуль отчетности не входит в текущий релиз, действия выгрузки/сохранения не должны отображаться либо должны быть помечены как недоступные согласно правилам продукта.

### 4.19. Просмотр результатов нескольких поисков на карте

**FR-IF-10-190.** Пользователь должен иметь возможность добавить на карту результаты нескольких поисков, если у него есть права на просмотр каждого набора результатов.

**FR-IF-10-191.** Для каждого добавленного поиска система должна отображать отдельный слой карты.

**FR-IF-10-192.** Система должна показывать легенду слоев с названием/идентификатором поиска, параметрами поиска и количеством событий.

**FR-IF-10-193.** Пользователь должен иметь возможность включать и выключать отображение каждого поискового слоя.

**FR-IF-10-194.** События разных поисков должны визуально различаться цветом, стилем маркера или подписью слоя.

**FR-IF-10-195.** При добавлении второго и каждого последующего поиска на карту система должна автоматически назначать новому поисковому набору цвет маркеров, отличный от цветов уже активных поисковых наборов.

**FR-IF-10-196.** Если свободные цвета палитры закончились, система должна дополнительно различать поисковые наборы стилем маркера, подписью или паттерном, сохраняя читаемость легенды.

**FR-IF-10-197.** Кластеры должны рассчитываться отдельно по каждому поисковому слою, если Пользователь не включил режим объединенного анализа.

**FR-IF-10-198.** В режиме объединенного анализа система должна показывать, из какого поиска пришло каждое событие внутри кластера или списка.

**FR-IF-10-199.** Если одно и то же событие входит в несколько поисков, система должна уметь отобразить его как пересечение и показать список поисков, в которых оно найдено.

**FR-IF-10-199.1.** При удалении поискового слоя с карты система не должна удалять результаты поиска из истории или хранилища.

**FR-IF-10-199.2.** После удаления последнего активного поискового слоя система должна возвращать карту к обычному представлению камер.

### 4.20. Перечень двойников. Будущий контур

**FR-FUT-IF-10-200.** Для заданного ТС система должна предоставлять перечень потенциальных двойников, если соответствующая функция включена в релизе.

**FR-FUT-IF-10-201.** Карточка потенциального двойника должна содержать номер ТС, регион, период фиксаций, географические зоны фиксаций, основание подозрения и ссылки на связанные события.

**FR-FUT-IF-10-202.** Система должна позволять перейти от записи двойника к журналу и карте связанных событий.

### 4.21. Перечень машин сопровождения. Будущий контур

**FR-FUT-IF-10-210.** Для заданного ТС система должна предоставлять перечень потенциальных машин сопровождения, если соответствующая функция включена в релизе.

**FR-FUT-IF-10-211.** Поиск сопровождения должен учитывать настраиваемый временной лаг относительно события исходного ТС.

**FR-FUT-IF-10-212.** Карточка машины сопровождения должна содержать номер ТС, количество совместных фиксаций, временной лаг, пересекающиеся точки и ссылки на события.

## 5. Нефункциональные требования

### 5.1. Производительность

**NFR-IF-10-001.** Для поисковой выдачи до 1000 событий журнал должен отображать первую страницу результатов не дольше чем за 2 секунды после получения данных от сервера.

**NFR-IF-10-002.** Для поисковой выдачи до 10000 событий журнал должен использовать пагинацию или виртуализацию и сохранять время отклика интерфейса на прокрутку не более 200 мс для 95% пользовательских действий.

**NFR-IF-10-003.** Переключение между журналом и картой без изменения параметров поиска должно занимать не более 1 секунды для уже загруженного набора до 10000 событий.

**NFR-IF-10-004.** Первичная отрисовка маркеров и кластеров на карте для набора до 10000 событий с координатами должна занимать не более 3 секунд после получения данных.

**NFR-IF-10-005.** Пересчет кластеров при изменении масштаба или области карты должен завершаться не более чем за 500 мс для видимой области с количеством событий до 5000.

**NFR-IF-10-006.** Открытие карточки сработки должно занимать не более 2 секунд для 95% запросов при нормальной доступности сервисов данных.

**NFR-IF-10-007.** Открытие фото в увеличенном виде должно занимать не более 3 секунд для 95% изображений размером до 5 МБ.

**NFR-IF-10-008.** Построение маршрутов для набора до 10000 событий должно занимать не более 5 секунд после получения данных.

**NFR-IF-10-009.** Расчет типовых точек для набора до 10000 событий должен занимать не более 5 секунд после получения данных.

### 5.2. Масштабируемость

**NFR-IF-10-020.** Архитектура должна поддерживать отображение результатов поиска объемом не менее 100000 событий через серверную пагинацию, агрегацию, кластеризацию или ленивую загрузку.

**NFR-IF-10-021.** Карта не должна пытаться одновременно отрисовывать более 5000 отдельных маркеров в видимой области без кластеризации или агрегации.

**NFR-IF-10-022.** Боковая панель должна использовать ленивую загрузку или виртуализацию при количестве карточек больше 500.

**NFR-IF-10-023.** Выгрузка отчетов должна выполняться асинхронно, если объем выгрузки превышает 10000 событий или расчет занимает больше 10 секунд.

### 5.3. Надежность и устойчивость к ошибкам

**NFR-IF-10-030.** Ошибка загрузки карты не должна блокировать просмотр журнала.

**NFR-IF-10-031.** Ошибка загрузки фото не должна блокировать просмотр метаданных карточки сработки.

**NFR-IF-10-032.** Ошибка открытия архивной точки не должна приводить к потере текущего контекста результатов поиска.

**NFR-IF-10-033.** При временной ошибке загрузки карточки, фото, карты или архива система должна предлагать повторить действие.

**NFR-IF-10-034.** Если часть событий повреждена или содержит неполные данные, система должна отображать корректные события и предметные статусы для неполных событий.

**NFR-IF-10-035.** Состояние выбранного события, фильтров и режима карты должно сохраняться при обновлении данных внутри текущей сессии.

### 5.4. Безопасность и разграничение доступа

**NFR-IF-10-040.** Все результаты, фотоматериалы, архивные потоки и отчеты должны отображаться только с учетом прав Пользователя.

**NFR-IF-10-041.** Если Пользователь не имеет права на устройство, событие с этого устройства не должно отображаться в результатах.

**NFR-IF-10-042.** Если Пользователь имеет право видеть метаданные события, но не имеет права на фото, система должна скрывать фото и показывать причину ограничения.

**NFR-IF-10-043.** Если Пользователь не имеет права на архив, действие перехода к архивной точке должно быть недоступно.

**NFR-IF-10-044.** API результатов поиска не должен возвращать фотоматериалы и ссылки на архивные потоки без проверки прав доступа.

**NFR-IF-10-045.** Все действия открытия карточки, просмотра фото, перехода к архиву и формирования выгрузки должны логироваться для аудита.

**NFR-IF-10-046.** В журналах аудита должны фиксироваться идентификатор Пользователя, идентификатор события, тип действия, дата и время действия, результат проверки доступа.

### 5.5. Конфиденциальность и защита данных

**NFR-IF-10-050.** Выгрузки результатов должны содержать только поля, доступные Пользователю в интерфейсе.

**NFR-IF-10-051.** Ссылки на фотоматериалы и архивные потоки должны быть защищены от несанкционированного доступа и не должны быть бессрочными публичными ссылками.

**NFR-IF-10-052.** При сохранении отчетов в личном кабинете система должна применять те же правила доступа, что и при просмотре результатов.

**NFR-IF-10-053.** При удалении или отзыве прав Пользователя сохраненные отчеты и ссылки на материалы должны становиться недоступными, если это предусмотрено политикой безопасности продукта.

### 5.6. Доступность и удобство использования

**NFR-IF-10-060.** Основные действия журнала, карты, боковой панели и карточки сработки должны быть доступны с клавиатуры.

**NFR-IF-10-061.** Элементы управления должны иметь видимый фокус при навигации с клавиатуры.

**NFR-IF-10-062.** Цветовое выделение маршрутов, кластеров, поисковых слоев и топ-5% типовых точек должно дублироваться текстом, иконкой или подписью.

**NFR-IF-10-063.** Состояния "Нет данных", "Нет координат", "Нет фото", "Нет прав" должны быть выражены текстом, а не только иконкой.

**NFR-IF-10-064.** Интерфейс должен сохранять читаемость при стандартном масштабировании браузера до 200%.

**NFR-IF-10-065.** Сообщения об ошибках должны быть понятными Пользователю и не должны содержать технические stack trace или внутренние идентификаторы без необходимости.

### 5.7. Совместимость

**NFR-IF-10-070.** Интерфейс должен поддерживать актуальные версии Chromium-based браузеров и Firefox, используемые в целевой инфраструктуре.

**NFR-IF-10-071.** Картографическое представление должно корректно работать при стандартных разрешениях экрана от 1366x768 и выше.

**NFR-IF-10-072.** Табличное представление должно корректно работать при ширине экрана от 1024 пикселей за счет горизонтальной прокрутки, адаптивного набора колонок или пользовательской настройки колонок.

### 5.8. Консистентность данных

**NFR-IF-10-080.** Журнал, карта, боковая панель, карточка сработки и выгрузка должны использовать один и тот же идентификатор события.

**NFR-IF-10-081.** Время фиксации должно отображаться в едином часовом поясе, заданном настройками системы или профиля Пользователя.

**NFR-IF-10-082.** Формат даты и времени должен быть единым во всех представлениях результатов.

**NFR-IF-10-083.** Если данные события обновились после выполнения поиска, система должна явно обозначать устаревшее или недоступное событие при попытке открыть карточку.

**NFR-IF-10-084.** Фильтрация, сортировка, кластеризация и маршруты должны строиться на одном и том же текущем наборе результатов или явно показывать, что используется другой набор.

### 5.9. Наблюдаемость и диагностика

**NFR-IF-10-090.** Система должна собирать метрики времени загрузки журнала, карты, карточки сработки, фото, маршрутов и типовых точек.

**NFR-IF-10-091.** Система должна фиксировать ошибки загрузки данных, карты, фото, архива и отчетов с техническим кодом ошибки.

**NFR-IF-10-092.** Для каждого пользовательского сценария должна быть возможность связать frontend-событие с backend-запросом через correlation id или аналогичный механизм трассировки.

**NFR-IF-10-093.** Должны собираться метрики количества событий без координат, без фото и без доступной архивной точки для оценки качества данных.

### 5.10. Локализация

**NFR-IF-10-100.** Все пользовательские тексты интерфейса должны быть доступны на русском языке.

**NFR-IF-10-101.** Форматы даты, времени, чисел и координат должны соответствовать локали, принятой в продукте.

**NFR-IF-10-102.** В пользовательском интерфейсе не должны отображаться непереведенные технические ключи сообщений.

### 5.11. Конфигурируемость

**NFR-IF-10-110.** Порог близости координат для кластеризации должен задаваться настройкой продукта.

**NFR-IF-10-111.** Порог временного разрыва для разделения маршрута должен задаваться настройкой продукта.

**NFR-IF-10-112.** Состав колонок журнала должен расширяться без изменения базового сценария просмотра результатов.

**NFR-IF-10-113.** Набор форматов выгрузки должен подключаться через конфигурацию модуля отчетности, если модуль отчетности используется.

### 5.12. Тестируемость

**NFR-IF-10-120.** Для функциональности журнала должны быть подготовлены тестовые наборы с событиями: с полными данными, без координат, без фото, без архива, с ограниченными правами.

**NFR-IF-10-121.** Для карты должны быть подготовлены тестовые наборы: одиночные маркеры, совпадающие координаты, плотные группы маркеров, события на разных масштабах, события без координат.

**NFR-IF-10-122.** Для маршрутов должны быть подготовлены тестовые наборы: одно ТС за один день, одно ТС за несколько дней, несколько ТС за один день, маршрут с событиями без координат.

**NFR-IF-10-123.** Для типовых точек должны быть подготовлены тестовые наборы, проверяющие расчет топ-5%, округление вверх и обработку одинаковой частоты на границе выборки.

**NFR-IF-10-124.** Для просмотра нескольких поисков на карте должны быть подготовлены тестовые наборы с пересекающимися и непересекающимися событиями.
